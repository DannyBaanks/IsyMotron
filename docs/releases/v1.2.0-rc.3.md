# IsyMotron v1.2.0-rc.3 — security hardening and hackathon submission build

This release candidate supersedes v1.2.0-rc.2. It is the build referenced by the hackathon submission. There is no hosted demo: use these downloads, or the [demo video](https://youtu.be/CXpOxUFJMrI).

## What changed since rc.2

- **Link:** sealed replies are authenticated before a result is used, address failover continues after invalid replies, a negative `Content-Length` is rejected (it used to pin a handler thread), and the inbox is rewritten atomically.
- **Console:** a malformed or negative `Content-Length` returns 400 instead of an unhandled error.
- **Web dashboard:** `/api/dashboard` now requires its own visitor key (`ISYMOTRON_DASHBOARD_TOKEN`); the backend session token never leaves the server. The dashboard no longer reports an unverified receipt seal as verified, nor an `ALLOW` decision as an executed action.
- **Docs:** README and Devpost claims aligned to the evidence (Windows 10 and iPhone approval wording).
