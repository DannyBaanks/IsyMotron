This is a pre-release: `/releases/latest` stays on
[v1.0.0](https://github.com/DannyBaanks/IsyMotron/releases/tag/v1.0.0) until

Each asset ships with `smoke-<platform>.json`: the binary's SHA-256, the host
engines it attached and every smoke check it passed. A binary that starts is
not a host that acts; the matrix keeps those apart
([PLATFORM_SUPPORT.md](https://github.com/DannyBaanks/IsyMotron/blob/v1.1.0-rc.1/docs/PLATFORM_SUPPORT.md)).

## Verify before you run

```bash
sha256sum -c SHA256SUMS.txt
gh attestation verify IsyMotron-linux-x86_64.tar.gz --repo DannyBaanks/IsyMotron
```

Every asset is attested (Sigstore build provenance) by the workflow that built
it. None is code-signed: Windows SmartScreen warns on first run; on macOS clear
the quarantine flag after verifying (`xattr -d com.apple.quarantine IsyMotron`).

## What's new

### A real Linux host (M2)

- **`LinuxHost` (`linux-real/0.1`)**: the same five capabilities and the same
  two scope checks as Windows. The manifests are shared objects, not copies.
- **Parity suite**: [`tests/test_host_parity.py`](https://github.com/DannyBaanks/IsyMotron/blob/v1.1.0-rc.1/tests/test_host_parity.py)
  is one scenario table run against the native engine on Windows *and* Linux
  CI. Link escapes (junction / symlink), `..`, logical names, listings,
  launch fingerprints: same decision on both. The single row that differs,
  on purpose: a case variant of a root is the same directory on NTFS and a
  different one on ext4.
- **Linux-only hardening**: the opened descriptor is re-checked through
  `/proc/self/fd` (closing the resolve-then-open window), writes use
  `O_NOFOLLOW` against a verified directory, FIFOs and devices are refused,
  hard-linked files are never overwritten, listings never stat through a link.
  Each defense has a test that fails when it is removed (8 mutants, 8 caught).
- Grants on Linux live in `$XDG_CONFIG_HOME/isymotron/grants.json`.

### Security fix — Finding 10

Before this release, `isymotron host` on Linux ran the **Windows** engine. On a
case-sensitive filesystem its case-folding scope check let a root
`…/Photos` hand over `…/photos/loot.txt` — a directory never granted. Now
`hosts/native.py` is the only place that picks an engine, the Windows engine
refuses to start off Windows, and a regression test replays the attack.
Write-up: [FINDINGS.md, Finding 10](https://github.com/DannyBaanks/IsyMotron/blob/v1.1.0-rc.1/docs/FINDINGS.md#finding-10--on-linux-the-windows-engine-handed-over-a-directory-it-was-never-granted).

### Three-platform build and release (M1)

- Windows, Linux and macOS binaries from one tree, each smoke-tested on its own
  runner: starts, serves, refuses without a token, serves bundled data,
  answers `help`, stops without leaving an orphan and releases its port.
- One `SHA256SUMS.txt`, verified against the assets before publishing.
- Tags with `-rc` / `-beta` / `-alpha` publish as pre-releases.

### The runtime is standard-library only — again, and enforced

The avatar PNG surface had quietly started to require Pillow. It now uses a
small stdlib (`zlib`) PNG codec, cross-checked against Pillow in the tests
(all color types, bit depths, Adam7, all five filters, bounded inflate). A
test imports the whole runtime with site-packages hidden, so the claim cannot
silently break again. `requests` was also removed from the CLI tools.

### Fixes found along the way

- Windows CLI: `avatar lienzo` / `avatar editar` crashed on redirected output
  (cp1252 has no `✓`/`●`).
- Windows smoke: the one-file binary's child could outlive the test (tree kill
  now happens while the parent is alive; the port must be released).
- A test wrote into the runner's real profile on Windows (`USERPROFILE`).
